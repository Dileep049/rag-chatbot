# 🎓 Citizen Assistance AI — Viva Voice Preparation Guide

This document contains **30 detailed viva voce questions and answers** covering General AI, RAG Methodology, Vector Databases, FastAPI Backend, React Frontend, Security, and System Limitations.

---

## 🏛️ 1. General & Project Overview

### Q1: What is the Citizen Assistance AI project?
**Answer**: Citizen Assistance AI is a grounded, multilingual RAG (Retrieval-Augmented Generation) chatbot designed to answer citizen inquiries regarding official Indian government procedures, Aadhaar services, pension schemes, police complaints, vehicle impoundments, PAN cards, driving licences, and government schemes. It uses official indexed documents to provide accurate, grounded answers in English, Native Telugu script, and Telugu-English phonetic spelling.

### Q2: What problem does this project solve?
**Answer**: Official government procedures are often spread across long PDF documents and department websites. Citizens frequently struggle to find exact procedural steps, eligibility criteria, and required documents. Generic AI models often hallucinate legal sections, fees, and office procedures. This project solves that by grounding AI responses strictly in indexed official department documents with verified source citations.

### Q3: Who are the target users of this system?
**Answer**: Citizens seeking information about government services, senior citizens applying for pensions, vehicle owners dealing with traffic police impoundments, applicants needing lost Aadhaar/PAN/DL replacements, and government administrative staff managing document knowledge bases.

### Q4: Is this chatbot an official government service?
**Answer**: No. It is an AI-assisted informational guidance system that retrieves information from uploaded official documents. All responses include an informational disclaimer advising citizens to verify details with the official department authority.

## 🤖 2. Artificial Intelligence & RAG Methodology

### Q5: What is RAG (Retrieval-Augmented Generation)?
**Answer**: RAG is an architectural pattern that combines an information retrieval system with a generative Large Language Model (LLM). Instead of relying solely on the LLM's internal pre-trained memory, RAG first retrieves relevant document chunks from an external knowledge base (ChromaDB) and passes them as context in the prompt to generate factually grounded answers.

### Q6: Why did you choose RAG over fine-tuning an LLM?
**Answer**: Fine-tuning an LLM is expensive, slow, requires retraining whenever a policy changes, and can still hallucinate. RAG allows real-time knowledge updates simply by adding, updating, or deleting documents in ChromaDB without retraining the model. It also enables precise source citations (page numbers, document names, section titles).

### Q7: What are text embeddings?
**Answer**: Text embeddings are dense numerical vector representations of text strings (e.g. 1536 floating-point numbers) generated by neural networks (e.g. OpenAI `text-embedding-3-small` or HuggingFace transformers). Text strings with similar semantic meaning map to nearby points in vector space.

### Q8: What is semantic similarity search?
**Answer**: Semantic similarity search measures the geometric distance (such as Cosine similarity or Euclidean distance) between the vector embedding of a user question and document chunk embeddings. This allows matching queries to documents based on meaning rather than exact keyword overlap.

### Q9: Why is document chunking necessary?
**Answer**: Large PDF files contain thousands of words across multiple topics. Sending entire documents to an LLM is expensive, exceeds context window limits, and dilutes specific answers. Chunking divides documents into smaller, meaningful, overlapping text sections (e.g. 700 characters with 150 overlap) while preserving heading, page, and section metadata.

### Q10: What is Hybrid Retrieval?
**Answer**: Hybrid retrieval combines **semantic vector search** (which captures user intent and context) with **lexical BM25 keyword search** (which matches exact terms like *"Section 207"*, *"Form 49A"*, or *"BNSS Section 173"*). This ensures both high recall and high precision.

### Q11: What is score-based reranking?
**Answer**: Initial similarity search retrieves a broad candidate pool of chunks (e.g. 15 candidates). Reranking re-evaluates each chunk using a combined scoring formula that factors in exact keyword density, section heading matches, exact entity extraction, and category alignment to select the top 4 most relevant chunks.

### Q12: How does the Relevance Threshold prevent AI hallucinations?
**Answer**: If the top candidate chunk's relevance score falls below `RAG_RELEVANCE_THRESHOLD` (`0.20`), the system determines that the knowledge base lacks sufficient information. Instead of sending weak context to the LLM, it immediately triggers the anti-hallucination guardrail: *"I could not find sufficient information in the available official documents to answer this question."*

## 🗣️ 3. Multilingual & Voice Input Features

### Q13: How does the system handle queries in Telugu or Telugu-English?
**Answer**: The backend `QueryProcessor` detects Telugu script (`[\u0C00-\u0C7F]`) or Telugu-English phonetic keywords (`poyindi`, `cheyali`, `kavali`, `teesukunnaru`). It maps these terms into English search concepts for vector retrieval against the English knowledge base while instructing the LLM to reply naturally in the user's input language.

### Q14: How does Voice Input work in the frontend?
**Answer**: Voice input uses the browser's native Web Speech Recognition API (`webkitSpeechRecognition`). It captures audio, converts speech to text in real time with support for English (`en-IN`) and Telugu (`te-IN`), and populates the chat input box so the user can review and edit the text before sending.

### Q15: What happens if Web Speech API is unsupported in a user's browser?
**Answer**: The system detects browser compatibility gracefully and displays a user-friendly alert: *"Voice input is unavailable in this browser. Please type your question."* The standard text input continues to work normally.

## ⚡ 4. Backend & API Architecture

### Q16: Why did you select FastAPI for the backend?
**Answer**: FastAPI is an asynchronous, high-performance Python web framework based on ASGI and Starlette. It features native Pydantic data validation, automatic OpenAPI/Swagger documentation, fast execution speeds comparable to NodeJS/Go, and native support for async/await concurrency.

### Q17: How is conversation context and follow-up questions handled?
**Answer**: The chatbot maintains chat history state. When a follow-up question is asked (e.g. *"What documents do I need?"* after *"My Aadhaar card is lost"*), `ChatbotService` detects the historical context or uses LLM standalone query re-writing to combine the conversation into a single contextual search query (*"Lost Aadhaar card replacement required documents"*).

### Q18: What is topic switching?
**Answer**: Topic switching detects explicit category shifts (e.g. switching from Aadhaar questions to pension questions). When a new topic keyword is detected, historical topic context is cleared for retrieval to prevent old Aadhaar context from polluting new pension searches.

## 💾 5. Database & Vector Storage

### Q19: Why did you select ChromaDB?
**Answer**: ChromaDB is an open-source, lightweight, embedded vector database designed specifically for AI/LLM applications. It provides persistent disk storage, fast nearest-neighbor search, and built-in metadata filtering (`category`, `document`, `page`, `section`).

### Q20: How are document chunks uniquely identified in ChromaDB?
**Answer**: Each chunk receives a deterministic, stable chunk ID combining document name, category, page number, and chunk index (e.g. `aadhaar_official_guide.pdf_aadhaar_p2_c0`). This prevents duplicate indexing when a document is uploaded or re-indexed.

### Q21: What metadata is stored with each document chunk in ChromaDB?
**Answer**:
```json
{
  "document": "aadhaar_official_guide.pdf",
  "category": "aadhaar",
  "page": 2,
  "section": "Section 1: Procedure for Lost Aadhaar Card",
  "source": "official",
  "source_url": "https://myaadhaar.uidai.gov.in"
}
```

## 🔐 6. Authentication & Security

### Q22: How is Admin access protected?
**Answer**: Admin routes (`/admin`) and document management REST APIs (`POST /upload`, `GET /documents`, `DELETE`, `POST /reindex`) are protected by FastAPI dependencies (`require_admin`). They validate Base64 HMAC-SHA256 JWT Bearer tokens passed in the `Authorization: Bearer <token>` HTTP header.

### Q23: Why do you not trust frontend role verification?
**Answer**: Frontend state (such as `localStorage` or React state) can easily be manipulated by an attacker using browser developer tools. All security and role authorization decisions must be verified on the backend by decoding and cryptographically verifying the JWT signature.

### Q24: How are API keys and secrets protected?
**Answer**: Sensitive credentials (`OPENAI_API_KEY`, `JWT_SECRET`, `ADMIN_PASSWORD`) are stored exclusively in server environment variables (`.env`) and read via `app/config.py`. They are never included in frontend JavaScript bundles or committed to version control.

### Q25: What rate limiting and input validation mechanisms are implemented?
**Answer**:
- **Rate Limiting**: `security_and_rate_limit_middleware` tracks client IP requests (60 req/min for chat, 15 req/min for upload) returning `429 Too Many Requests`.
- **Input Validation**: Enforces 15MB file size caps, filename path traversal sanitization, supported file extension filtering (`.pdf`, `.docx`, `.txt`), and HTTP security headers (`X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`).

## 🎨 7. Frontend & User Experience

### Q26: Why did you build a ChatGPT-style conversational interface without category sidebars?
**Answer**: Citizen interactions should feel natural and effortless. Forcing users to select categories (Aadhaar, Pension, Police) before asking creates unnecessary friction. A unified ChatGPT-style interface accepts any question and lets the backend automatically detect categories and retrieve relevant documents.

### Q27: How does the Copy and Regenerate feature work?
**Answer**:
- **Copy**: `navigator.clipboard.writeText` copies visible answer text (excluding hidden metadata) and displays temporary `✓ Copied` feedback for 2 seconds.
- **Regenerate**: Resends the last user question while preserving conversation context to trigger fresh RAG retrieval and LLM answer generation.

## 📊 8. Limitations & Future Enhancements

### Q28: What are the main limitations of this system?
**Answer**:
1. Accuracy depends strictly on the quality and completeness of uploaded official documents.
2. Scanned image-only PDFs require OCR (Tesseract) pre-processing before ingestion.
3. Voice input relies on browser Web Speech API availability.

### Q29: What future enhancements can be added to this project?
**Answer**:
1. Integration with official government APIs (e.g. DigiLocker / UIDAI status APIs).
2. Advanced multi-modal RAG for processing document tables and infographics.
3. Text-to-Speech (TTS) audio answers in regional Indian languages.
4. Cloud vector database integration (e.g. Qdrant / Pinecone) for multi-tenant scalability.

### Q30: How did you test and evaluate the system?
**Answer**: We built an automated test runner (`test_full_suite.py`) executing 21 unit, integration, and security tests, achieving 100% pass rate. We also created a 30-question evaluation dataset (`tests/rag_questions.json`) covering all categories, multilingual queries, and out-of-domain queries to verify zero hallucination.
